## Four defects, all after the dry run passed

`FAILURE_LOG.md` F-016 through F-019a. Each was invisible to both the dry run and a
then-740-test suite, and each was caught by running one real chain and validating it.

| ID | What | Would have cost |
|---|---|---|
| F-016 | The launcher's budget guard asserted exact equality, which no configuration containing a control arm could satisfy. It fired on the frozen grid at a 0.04% spread | A run that flagged itself, with no way to tell from the exit code |
| F-017 | Corpus paths were passed relative and resolved against the upstream checkout | All 25 chains died in seconds. Caught immediately |
| F-018 | `validate_run.py` and `validation/audit.py` each carried their own copy of F-016's rule | 25 sound chains, every one certified invalid, after 7 hours |
| F-019 / F-019a | Partition provenance was declared under `data.manifests`, a vocabulary `build_partitions` did not read — and the first fix was verified against the config on disk rather than the config `chain_config` builds | Every chain uncertifiable, unrecoverably: provenance is written at chain start and cannot be back-filled |

The pattern is one thing, worth carrying forward: **a passing dry run certifies
arithmetic, not execution.** It prints the upstream command instead of running it, and it
never validates the manifest it wrote. `docs/RUNBOOK_PILOT_LAUNCH.md` §5a now requires one
real chain plus `validate_run.py` before any grid. That step found all four.
